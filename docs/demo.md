# Короткая демонстрация

1. Открыть `UI/index.html` в Chrome. На главной показать header, меню, личный кабинет и footer.
2. Через «Карта экранов» открыть «Пустой список». Вернуться на главную.
3. В каталоге выбрать «Сапборды», затем «Все», переключить сортировку на «Сначала дороже».
4. Открыть «Бронирование». Показать тип средства, площадку, услугу, дату, время, количество человек, оборудование и оплату. Развернуть поля заказа по телефону.
5. Оставить значения примера: 24.06.2027, 14:00, 2 часа, сапборд, индивидуальное обучение, 1 человек, жилет. Нажать «Проверить доступность», затем «Подтвердить бронирование».
6. Открыть «Мои брони», перейти на страницу 2 и обратно. Показать пример поиска по слову «Сапборд» и карточку № 1042.
7. Из карточки открыть редактирование, показать новое время 16:00 и результат изменения. Затем открыть подтверждение отмены и результат отмены.
8. Через «Карта экранов» показать ошибки: время 11:00 при текущем времени 10:00 и занятое средство. Ссылки возвращают к исправлению параметров.
9. Показать абонемент, заморозку, личное расписание инструктора и отчёт руководителя.
10. Открыть «Пользователи»: показать формы добавления, редактирования и удаления записи.

Важно для объяснения: это статический прототип интерфейса по заданию № 5. Результаты операций заранее подготовлены. Список броней не изменяется после демонстрации создания или отмены. Вход и роли не обеспечивают реальную защиту доступа.

## Что можно объяснить по коду

- `header`, `nav`, `main`, `section`, `article`, `aside`, `footer` задают смысл блоков.
- Ссылка ведёт на `#id` раздела. CSS показывает `.screen:target`, а при отсутствии известного якоря — главную.
- `label` связан с полем по `for` и `id`. Для групп используются `fieldset` и `legend`.
- Grid задаёт основные колонки и формы, Flexbox — действия, списки и диаграмму.
- Медиазапросы перестраивают страницу на узких экранах.
- `:has()` реагирует на выбранную радиокнопку фильтра или сортировки, `order` меняет порядок карточек.
- `required`, `min`, `max`, `minlength` обеспечивают только встроенную проверку полей браузером. Бизнес-правила требуют отдельной логики.
